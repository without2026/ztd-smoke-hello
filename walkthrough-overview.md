# ztd-smoke-hello — Walkthrough

## 1. What this app does (in one paragraph)

An Android app that opens to a single screen showing the word **"Hello"** centered on the display. That's it — no buttons, no navigation, no network calls. It exists as a **smoke test**: a minimal end-to-end target that proves the team's zero-to-deploy pipeline (code generation → build → test → CI) works. If this builds and launches, the pipeline is healthy. It's meant to be thrown away after validation.

## 2. Tech stack cheat-sheet

| Layer | Tech | What it is in one line |
|---|---|---|
| Language | **Kotlin** 1.9.24 | Modern JVM language; what Android apps are written in today (replacing Java). |
| Platform | **Android SDK** 34 (min 26) | Runs on Android 8.0+; "compileSdk 34" = code can use APIs up to Android 14. |
| Build | **Gradle 8.5** with Kotlin DSL | Turns source code + resources into an `.apk` file. `build.gradle.kts` is the config. |
| UI | **XML layout** (old-school views, not Jetpack Compose) | Screens are declared in XML files under `res/layout/`. |
| Tests | **JUnit 4** + **Robolectric** | Robolectric lets Android tests run on your laptop (JVM) without an emulator. |
| CI | **GitHub Actions** (`.github/workflows/pr.yml`) | Runs build + tests automatically on every pull request. |

## 3. Entry points — where execution actually starts

- **On a phone**: Android OS reads `AndroidManifest.xml`, sees `MainActivity` is tagged with `action.MAIN` + `category.LAUNCHER`, and starts it. That triggers `MainActivity.onCreate(...)`.
- **For a build**: `./gradlew :app:assembleDebug` reads `settings.gradle.kts` → loads `app/build.gradle.kts` → compiles everything under `app/src/main/` → bundles into an APK.
- **For tests**: `./gradlew :app:test` runs everything in `app/src/test/` (i.e., `MainActivityTest.kt`).

## 5. Recommended reading order

1. **`AndroidManifest.xml`** (~15 lines) — the OS entry point. See how Android finds your activity.
2. **`MainActivity.kt`** (~18 lines) — where execution starts in Kotlin code. This is the entire "app logic".
3. **`res/layout/activity_main.xml`** (~15 lines) — the UI that `MainActivity` displays. Note the `@+id/hello_text` — that ID is what the test looks up.
4. **`res/values/strings.xml`** (~6 lines) — see how `@string/hello_message` in the layout resolves to `"Hello"`.
5. **`MainActivityTest.kt`** (~45 lines) — once you understand what the app does, read how it's tested. Robolectric spins up a fake Android runtime in plain JVM.
6. **`app/build.gradle.kts`** (~35 lines) — the build config. Skim to see which dependencies exist.

Following this order builds the mental model the way Android itself works: manifest → activity → layout → strings → tests.

## 6. Language-specific gotchas you'll hit

**Kotlin (new to you)**
- `class MainActivity : Activity()` — the `:` means "extends". In Python/Java you'd write `extends Activity`.
- `override fun onCreate(savedInstanceState: Bundle?)` — `fun` = function, `Bundle?` = "Bundle OR null" (the `?` is critical — it's Kotlin's null-safety).
- `super.onCreate(...)` — calls the parent class's version. Exactly like Java.
- `R.layout.activity_main` — `R` is auto-generated by the build. It's a big class of integer IDs for every resource. `R.layout.activity_main` resolves to an int that identifies the XML layout file.

**Android framework (new conceptually)**
- **`Activity`** = one screen. Lifecycle (`onCreate` → `onStart` → `onResume` → `onPause` → `onStop` → `onDestroy`) is driven by the OS, not by you. You only override the hooks you care about; here, only `onCreate`.
- **`Bundle`** = the saved-state packet Android hands you if the user rotated the screen or the OS killed & restored your app. `null` on a fresh launch.
- **`setContentView(R.layout.activity_main)`** = "use this XML file as my screen". Android inflates the XML into real View objects at runtime.

**Robolectric (in the test file)**
- Normally Android tests need a phone or emulator. Robolectric fakes the entire Android runtime in a regular JVM unit test, so `./gradlew test` runs in seconds on your laptop. Wherever you see `Robolectric.buildActivity(...)`, that's Robolectric pretending to be the OS.
