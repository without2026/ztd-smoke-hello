# Trace: cold launch → "Hello" on screen

What happens between the user tapping the app icon and the word "Hello" painting on screen. Cold start (app not already running).

## Call chain (at a glance)

```
OS (launcher tap)
 └─► AndroidManifest.xml:10-13   (LAUNCHER intent filter → MainActivity)
      └─► MainActivity.kt:13      (onCreate)
           └─► MainActivity.kt:14 (super.onCreate)
           └─► MainActivity.kt:15 (setContentView(R.layout.activity_main))
                └─► LayoutInflater (framework-internal)
                     └─► res/layout/activity_main.xml:2-14 (LinearLayout + TextView)
                          └─► activity_main.xml:12 (android:text="@string/hello_message")
                               └─► res/values/strings.xml:4 ("Hello")
 └─► OS (onStart → onResume → paint)
```

*(Links for each step are in the expanded breakdown below — click to jump to code.)*

## Step by step

### 1. OS picks the entry point

**Where:** [`app/src/main/AndroidManifest.xml:7-14`](./app/src/main/AndroidManifest.xml#L7-L14)
**What:** The OS's launcher reads every installed app's manifest. For this app, it finds exactly one activity ([`MainActivity`](./app/src/main/java/com/without/hellosmoke/MainActivity.kt#L12)) with the intent filter [`action.MAIN` + `category.LAUNCHER`](./app/src/main/AndroidManifest.xml#L10-L13) — Android's convention for "show me in the app drawer; start me when tapped". Android's ActivityManagerService instantiates the class by its fully-qualified name: `.MainActivity` resolves against the implicit package [`applicationId = "com.without.hellosmoke"` in `app/build.gradle.kts:11`](./app/build.gradle.kts#L11).
**Handoff:** **Manifest → class, by class name (reflection).** The manifest is the *only* thing that knows `MainActivity` is the entry point — there is no `main` function in the Kotlin code.

### 2. Android instantiates `MainActivity` and calls `onCreate`

**Where:** [`app/src/main/java/com/without/hellosmoke/MainActivity.kt:12-16`](./app/src/main/java/com/without/hellosmoke/MainActivity.kt#L12-L16)
**What:** The OS creates a `MainActivity` instance (no-arg constructor inherited from `Activity`) and calls [`onCreate(savedInstanceState=null)`](./app/src/main/java/com/without/hellosmoke/MainActivity.kt#L13) on the main thread. `null` because this is a cold start — no previous state to restore.
**Handoff:** **OS → activity, via lifecycle hook.** `onCreate` is never called by user code in this app; the framework invokes it.

### 3. Base-class bookkeeping

**Where:** [`MainActivity.kt:14`](./app/src/main/java/com/without/hellosmoke/MainActivity.kt#L14) — `super.onCreate(savedInstanceState)`
**What:** Delegates to `Activity.onCreate` (framework) which sets up the Window, restores state from the Bundle (null here), wires input dispatch, etc. Skipping this would crash at runtime with `SuperNotCalledException`.
**Handoff:** Intra-class super call. Not a cross-file boundary, but listed because forgetting this is one of the most common Android bugs.

### 4. Layout gets inflated

**Where:** [`MainActivity.kt:15`](./app/src/main/java/com/without/hellosmoke/MainActivity.kt#L15) — `setContentView(R.layout.activity_main)`
**What:** `R.layout.activity_main` is a build-generated int constant. At runtime the framework maps that int back to the XML file [`res/layout/activity_main.xml`](./app/src/main/res/layout/activity_main.xml). `setContentView` hands the int to Android's `LayoutInflater`, which parses the XML, constructs a [`LinearLayout`](./app/src/main/res/layout/activity_main.xml#L2-L6) containing one [`TextView`](./app/src/main/res/layout/activity_main.xml#L8-L13), and attaches the tree to the Activity's window as the content view.
**Handoff (the important one):** **Kotlin code → XML resource, by generated integer ID.** The human-readable link is the name `activity_main`; the runtime link is an integer. The `R` class is generated by the Android build (AAPT2) — do not search for it in source.

### 5. TextView resolves its display text

**Where:** [`res/layout/activity_main.xml:12`](./app/src/main/res/layout/activity_main.xml#L12) — `android:text="@string/hello_message"`
**What:** During inflation the `TextView` constructor sees [`android:text="@string/hello_message"`](./app/src/main/res/layout/activity_main.xml#L12) and looks up the string resource by name in the app's compiled resource table. That table is built from every `<string>` in `res/values/*.xml`. `hello_message` resolves to [`strings.xml:4`](./app/src/main/res/values/strings.xml#L4) → `"Hello"`. The TextView stores that string and will render it once the layout/measure/draw pass runs.
**Handoff:** **Layout XML → strings XML, by resource name.** The two files never import each other; they couple through the name `hello_message` and the build's resource table. Renaming one side without the other breaks at compile time (aapt error), not runtime.

### 6. Paint

**Where:** OS, after [`onCreate`](./app/src/main/java/com/without/hellosmoke/MainActivity.kt#L13) returns.
**What:** Android advances the lifecycle (`onStart` → `onResume`), then runs the first layout/measure/draw pass on the window. Pixels hit the screen showing "Hello" centered — [`LinearLayout` has `gravity=center` + `orientation=vertical`](./app/src/main/res/layout/activity_main.xml#L5-L6), [`TextView` at `textSize=32sp`](./app/src/main/res/layout/activity_main.xml#L13).
**Handoff:** OS-driven; no code in this app runs after step 5.

## Handoffs summary

The skeleton of this app is five boundary crossings. Four of them are **non-code** handoffs — the thing that's frustrating about Android if you're used to pure-code apps.

| # | From | To | Mechanism | Resolved when |
|---|---|---|---|---|
| 1 | OS launcher | [`MainActivity`](./app/src/main/java/com/without/hellosmoke/MainActivity.kt#L12) | [Manifest declaration](./app/src/main/AndroidManifest.xml#L7-L14) + class-name reflection | Install time / launch time |
| 2 | OS | [`onCreate`](./app/src/main/java/com/without/hellosmoke/MainActivity.kt#L13) | Lifecycle hook (framework calls into your class) | Every launch |
| 3 | Kotlin | [Layout XML](./app/src/main/res/layout/activity_main.xml) | `R.layout.*` generated int ID | Build time (ID generation) + runtime (inflation) |
| 4 | [Layout XML](./app/src/main/res/layout/activity_main.xml#L12) | [strings XML](./app/src/main/res/values/strings.xml#L4) | `@string/*` resource reference | Build time (resource merge) + runtime (TextView init) |
| 5 | Framework | Screen | Layout/measure/draw pass | Frame time after `onResume` |

Only handoff #1 requires knowing Android conventions you can't see from Kotlin alone. The rest are within the framework's own pipeline once `onCreate` runs.

## What to ask next

Pick whichever:

1. **"Trace what happens on screen rotation"** — different path: `onSaveInstanceState` → `onDestroy` → new `MainActivity` instance → `onCreate(savedInstanceState=<Bundle>)`. The Bundle piece only matters once you save state.
2. **"Profile [`MainActivity.kt`](./app/src/main/java/com/without/hellosmoke/MainActivity.kt)"** — card with callers, callees, side effects. Short (one public method) but useful as a Profile template for larger files later.
3. **"Map every reference to `R.layout.activity_main` and `R.string.hello_message`"** — Reference Map across Kotlin + XML. Shows how resource IDs appear in both production code and tests.
4. **"Trace what the JVM test path does in [`MainActivityTest.kt`](./app/src/test/java/com/without/hellosmoke/MainActivityTest.kt)"** — Robolectric fakes steps 1-2; the rest of the pipeline is real. Good contrast to the on-device trace.
